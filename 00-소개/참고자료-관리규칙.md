# 참고자료 관리 규칙

## 목적
참고자료를 “쌓아두는 링크 모음”이 아니라,
문서의 신뢰도를 유지하고 다시 찾기 쉬운 형태로 관리한다.

## 참고자료의 범위
- 공식 문서 / 표준 문서 / 스펙
- 기술 블로그/아티클
- 영상/강의
- 책(챕터 단위로 기록 권장)
- 이슈/PR/토론(근거가 되는 경우)

## 기록 위치/원칙
- ㅊ마고자료의 "목록"은 `appendix/참고자료.md`에 누적한다.
- 각 문서 하단의 `참고자료` 섹션에는 "그 문서에 직접 사용한 것"만 둔다.
- 외부 링크는 가능하면 "왜 참고했는지(1줄)"를 함께 적는다.

## 참고자료 기록 포맷(권장)
각 항목은 아래 정보를 포함한다.

- 제목 - 링크
  - 유형: (공식/스펙/아티클/영상/책/이슈)
  - 사용 위치: (어떤 문서에서 인용/근거로 사용했는지)
  - 확인일: YYYY-MM-DD
  - 메모: (핵심 요지 1~2줄)

예시:

- MDN - Event loop
  - 유형: 공식
  - 사용 위치: 03-언어-코어/javascript/이벤트루프-태스크-마이크로태스크.md
  - 확인일: 2026-01-23
  - 메모: 브라우저 이벤트 루프 개념 정의/용어 정리

## 신뢰도 우선순위(권장)
1) 표준/스펙/공식 문서
2) 메이저 레퍼런스(MDN 등) / 잘 관리되는 프로젝트 문서
3) 유명 엔지니어링 블로그(근거/실험 포함)
4) 개인 블로그/영상(검증 필요)

## 갱신/폐기 규칙
- 도구/프레임워크 관련 링크는 시간이 지나면 내용이 바뀔수 있으므로 "확인일"을 필수로 남긴다.
- 문서 내용의 핵심근거로 쓰인 링크가 오래되면 재확인한다.
- 링크가 꺠졌거나 내용이 바뀌어 근거로 부적절해지면:
  - 대체 링크로 교체 + 변경 이유 기록
  - 필요하면 문서에 `DEPRECATED` 또는 "주의" 문구 추가

## 인용/표절 주의(개인용이라도 권장)
- 긴 문장/도표를 그대로 옮기지 않는다.
- 핵심은 요약하고, 원문 링크로 연결한다.
