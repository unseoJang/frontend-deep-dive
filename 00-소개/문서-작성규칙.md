# 문서 작성 규칙

## 기본 구조

모든 학습 문서는 다음 순서를 기본으로 한다.

1. 학습 목표
2. 먼저 답해보기
3. 핵심 정의(What)
4. 필요한 이유(Why)
5. 동작 원리(How)
6. 예제와 검증
7. 자주 하는 오해
8. 30초 설명
9. 완료 체크리스트
10. 참고자료와 마지막 업데이트

주제에 필요하지 않은 섹션은 억지로 만들지 않는다.

## 작성 원칙

- 첫 문단에서 이 문서를 읽고 무엇을 설명할 수 있어야 하는지 밝힌다.
- 정의는 짧고 단정적으로 쓴다.
- 스펙 용어 뒤에는 일상어 설명을 붙인다.
- 결과만 적지 말고 결과가 나온 이유를 적는다.
- 한 코드 예제에서는 확인할 개념을 1~3개로 제한한다.

## 코드 예제 형식

코드에는 언어를 명시하고 다음 순서로 설명한다.

```text
예상 → 실행 → 실제 결과 → 원인
```

명령이 있다면 성공 결과와 실패 시 확인할 지점을 함께 적는다.

## 표현 규칙

- 제목은 `#` 하나만 사용한다.
- 섹션은 `##`, 하위 섹션은 `###`까지만 사용한다.
- 한글 용어와 영문 용어는 처음 한 번만 함께 쓴다.
- `실행 컨텍스트 = 객체`처럼 구현을 단정하는 비유는 피한다.
- “코드가 위로 올라간다”처럼 오해를 만드는 표현은 정확한 모델로 바꾼다.

## 분량 기준

한 번의 학습에서 읽고 검증할 수 있는 길이를 우선한다. 심화 내용이 핵심 흐름을 끊으면 별도 문서로 분리하고 링크한다.
