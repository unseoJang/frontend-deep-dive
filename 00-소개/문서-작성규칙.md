# 문서 작성 규칙

## 목적
이 레포의 모든 문서를 "같은 형식/품질/가독성"으로 작성하기 위한 규칙을 정의한다.

## 문서 기본 구조(권장 템플릿)
문서는 아래 순서를 기본으로 한다.

1. 목적(이 문서를 읽고 얻는 결과)
2. 전제(환경/선행지식/범위)
3. 핵심 개념
   - 정의(What) → 원리(How) → 이유(Why)
4. 예시
   - 코드/시나리오/그림 중 1개 이상
5. 검증 방법(가능한 경우)
   - 체크리스트/재현 절차
6. 자주 하는 실수/오해
7. 요약(3~7줄)
8. 참고자료
9. 마지막 업데이트: YYYY-MM-DD

## 헤딩/스타일 규칙
- 문서 제목은 `#` 1개만 사용한다.
- 섹션은 `##`, 하위는 `###`까지를 기본으로 한다.
- 한 문단이 길어지면 분리한다(가독성 우선).
- 강조는 핵심에만 `**굵게**` 사용한다(남용 금지).

## 용어/표기 규칙
- 최초 등장 시 한글+영문 병기 후, 이후에는 한 가지 표기로 통일한다.
  - 예: 이벤트 루프(Event Loop) → 이후 “이벤트 루프”
- 약어는 최초 1회 풀어서 쓴다.
  - 예: CRP(Critical Rendering Path)
- "정의" 문장은 단정형으로, "가정/선택"은 조건을 붙여 구분한다.
  - 예: "~이다" vs "~일 수 있다(조건: ...)"

## 코드/명령 작성 규칙
- 코드 블록은 언어를 명시한다: `ts`, `js`, `bash` 등
- 명령은 가능한 경우 아래 형식을 따른다.
  - 명령 → 기대 결과 → 실패 시 확인 포인트
- 코드 예시는 "핵심만 남기고" 불필요한 주변 코드는 제거한다.

## 예시/검증/트러블슈팅 규칙
- 예시는 최소 1개 이상 포함한다.
- 검증은 가능한 경우 "체크리스트"로 제공한다.
- 트러블슈팅은 아래 형식을 따른다.
	1) 증상 2) 원인 후보 3) 확인 방법 4) 해결 순서

## 결론/요약 규칙
- 요약은 "암기 카드"처럼 쓰되, 근거 없는 결론만 남기지 않는다.
- "핵심 문장 3개 + 실전 포인트 2개" 정도가 가장 재사용성이 높다.

## 금지/지양
- "대충/알아서/적당히" 같은 모호한 표현 금지
- 근거 없는 단정 금지(특히 성능/보안/비용)
- 환경 의존 문장은 조건을 명시(OS/브라우저/버전/네트워크 등)
