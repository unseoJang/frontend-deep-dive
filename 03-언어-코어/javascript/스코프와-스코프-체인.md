# 스코프와 스코프 체인

```js
const value = 1;

function outer() {

  function inner() {
    console.log(value);
  }

  inner();
}
```

## 스코프란?

스코프(Scope)는 변수나 함수 같은 **식별자를 참조할 수 있는 범위**다.

```js
const value = 1;

function outer() {
  const value = 2;

  function inner() {
    console.log(value);
  }

  inner();
}

outer(); // 2
```

`inner` 스코프에 `value`가 없더라도 `outer` 스코프에 있는 `value`를 참조할 수 있다. 같은 이름의 식별자가 여러 범위에 있을 수 있기 때문에, JavaScript는 식별자를 찾는 규칙을 사용한다.

## 스코프 체인이란?

스코프 체인(Scope Chain)은 현재 스코프에서 식별자를 찾지 못했을 때 바깥 스코프로 이동하며 탐색하는 경로다.

```text
inner 스코프
↓ 찾지 못하면
outer 스코프
↓ 찾지 못하면
전역 스코프
```

현재 스코프에서 식별자를 찾으면 탐색을 멈춘다. 모든 바깥 스코프를 확인했는데도 찾지 못하면 `ReferenceError`가 발생한다.

### 식별자 탐색 예시

```js
const value = 1;

function outer() {
  const value = 2;

  function inner() {
    console.log(value);
  }

  inner();
}

outer();
```

`inner()`에서 `value`를 만났을 때의 탐색은 다음과 같다.

```text
1. inner 스코프에 value가 있는가? → 없음
2. outer 스코프에 value가 있는가? → 있음, 2
3. 탐색 종료
```

따라서 출력은 `2`다. 전역의 `value`까지 이동하지 않는 이유는 더 가까운 `outer` 스코프에서 이미 찾았기 때문이다.

## 왜 필요한가?

스코프 체인은 현재 범위에 없는 식별자를 **어디에서 계속 찾아야 하는지** 결정한다. 이 규칙이 없으면 중첩 함수에서 같은 이름을 사용할 때 어떤 값을 참조해야 하는지 결정할 수 없다.

스코프 체인은 함수 자체를 연결한 목록이 아니다. 식별자 탐색을 위해 현재 렉시컬 환경에서 바깥 환경으로 이어지는 경로다.

## 렉시컬 스코프

JavaScript는 렉시컬 스코프(Lexical Scope), 또는 정적 스코프를 사용한다. 식별자를 찾는 바깥 경로가 함수의 **호출 위치가 아니라 정의 위치**를 기준으로 결정된다는 뜻이다.

```js
const value = 1;

function outer() {
  const value = 2;

  return function inner() {
    console.log(value);
  };
}

const fn = outer();

function run() {
  const value = 3;
  fn();
}

run(); // 2
```

`inner()`는 `run()` 안에서 호출되지만 `3`이 아니라 `2`를 출력한다. `inner`가 `outer` 안에서 정의됐기 때문에, `inner`의 스코프 체인은 다음처럼 만들어진다.

```text
inner
↓
outer
↓
global
```

`run`은 `inner`의 정의 위치 바깥에 없으므로 이 체인에 포함되지 않는다. 이 예제는 스코프 체인과 클로저가 연결되는 지점이기도 하다. 반환된 `inner` 함수가 `outer` 환경을 참조하기 때문이다.

## 헷갈리기 쉬운 점

### “가까운 값”은 실행 시점의 거리가 아니다

현재 코드에서 실행 중인 함수와 가까운 값을 고르는 것이 아니다. 선언 위치로 결정된 스코프 체인에서 현재 스코프에 가까운 바인딩을 먼저 찾는다는 뜻이다.

### 객체 프로퍼티 탐색과 다르다

`obj.value`는 객체의 프로퍼티를 찾는 동작이다. `value`처럼 객체 없이 식별자를 찾는 동작이 스코프 체인을 따른다.

### 함수가 호출되면 스코프 체인이 새로 바뀌는 것은 아니다

함수 호출로 실행 컨텍스트는 새로 만들어지지만, 렉시컬 스코프의 바깥 경로는 함수가 정의된 구조를 기준으로 결정된다.

## 직접 검증하기

1. 위의 `fn` 예제를 브라우저 Console에 실행한다.
2. `inner` 내부의 `console.log`에 `debugger`를 추가한다.
3. Scope 패널에서 `Closure`와 `Local` 영역을 확인한다.
4. `value`가 `outer`의 바인딩인 `2`로 해석되는지 확인한다.
5. `run`의 `value = 3`이 탐색 대상에 포함되지 않는 이유를 한 문장으로 설명한다.

## 면접 답변

> 스코프는 식별자를 참조할 수 있는 범위입니다. 스코프 체인은 현재 스코프에서 식별자를 찾지 못했을 때 바깥 스코프로 이어서 탐색하는 경로입니다. JavaScript는 렉시컬 스코프를 사용하기 때문에 함수의 스코프는 호출된 위치가 아니라 코드가 정의된 위치를 기준으로 결정됩니다.

## 기억할 것

```text
스코프
= 식별자를 참조할 수 있는 범위

스코프 체인
= 현재 스코프 → 바깥 스코프로 식별자를 찾는 경로

렉시컬 스코프
= 호출 위치가 아니라 정의 위치 기준
```
